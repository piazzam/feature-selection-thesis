# Solution Concepts for Feature Selection on Tabular Data

Code accompanying the thesis chapter **“Solution Concepts for Feature Selection on Tabular Data.”**

The experiments study a performance-based cooperative game for global feature selection. Input features are the players; the value of a coalition is the predictive performance of a model trained using only the corresponding feature subset, relative to a majority-class baseline. The resulting feature rankings are compared across different cooperative-game solution concepts and against classical feature-selection methods.

## Scope

This repository contains the code for both experimental regimes considered in the chapter:

- **Exact coalition evaluation** for low-dimensional datasets, where all coalitions can be evaluated.
- **Approximate coalition evaluation** for higher-dimensional datasets, where solution concepts are estimated from sampled coalitions.

The main solution concepts implemented are:

- Shapley value;
- additively normalised Banzhaf index;
- egalitarian least core;
- EX-L1;
- EX-Linf.

The approximate experiments compare four coalition-sampling strategies:

- **Base:** empty set, all singletons, all size-`n-1` coalitions, and the grand coalition (`2n+2` coalitions);
- **Random:** Base plus `2n` uniformly sampled coalitions;
- **KernelSHAP:** KernelSHAP-style sampling with nominal budget `2n + 2048 + 2`;
- **Uniform:** uniform sampling over the coalition space with the same nominal budget as KernelSHAP.

Two predictive models are supported: logistic regression (`lr`) and random forest (`rf`). The code also contains the classical baselines used in the experiments: SFS, SBS, LASSO, and RFE.

└── src/
    ├── cooperative_game_theory.py

`src/cooperative_game_theory.py` implements the cooperative-game solution concepts and coalition-sampling procedures. `src/experiment.py` contains model training, evaluation, feature-selection baselines, result aggregation, and utility functions. `src/generation.py` contains the dataset-specific experimental pipelines.

## Installation

Python 3.10+ is recommended.

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

The optimisation routines use **Gurobi** through `gurobipy`. A working Gurobi installation/license is therefore required for the least-core and excess-norm optimisation routines. See the Gurobi documentation for the licence option appropriate to your environment.

## Data

Most datasets are downloaded directly from **UCI** or **OpenML** by `src/generation.py`. They are therefore not included in the repository.

A small number of datasets were originally loaded from local files. Their expected filenames and directory structure are listed in [`data/README.md`](data/README.md). Place those files under a top-level `DATA/` directory before running the corresponding experiments.

Generated datasets, downloaded data, intermediate coalition values, and experimental results should not be committed to Git and are excluded through `.gitignore`.

## Exact-regime experiments

The exact regime enumerates the full coalition space and computes the allocations without coalition sampling.

Example:

```bash
python scripts/run_exact.py --dataset iris --model lr
```

Supported exact-regime dataset identifiers in the supplied final code are:

```text
iris
banknote
monks1
monks3
raisin
breastcancer
magic
australian
seismic
heart
```

Run the same experiment with random forest by replacing `--model lr` with `--model rf`.

## Approximate-regime experiments

The approximate regime generates the Base, Random, KernelSHAP, and Uniform coalition samples and evaluates the corresponding approximate allocations.

Example:

```bash
python scripts/run_approx.py --dataset sonar --model lr
```

Individual repeated-holdout repetitions can be selected, which is useful on a cluster:

```bash
python scripts/run_approx.py \
  --dataset sonar \
  --model rf \
  --repeat-start 0 \
  --repeat-end 1
```

The supplied final code contains loaders for the complete collection of higher-dimensional datasets used during development, including Sonar, Spambase, Chess, Parkinsons, Hepatitis, Nursery, Dermatology, Satimage, Mushrooms, Splice, Robot Navigation, QSAR, Indian Liver Patient, Image Segmentation, Tic-Tac-Toe, Libras, Musk, COIL2000, Optical Digits, and the other datasets listed in `scripts/run_approx.py`.

## EX-L1 and EX-Linf

The EX-L1 and EX-Linf stage reuses coalition values generated by the approximate-regime experiment. Run the approximate experiment first, then:

```bash
python scripts/run_excess_norms.py --dataset sonar --model lr
```

## Output

The original experimental code writes intermediate and final outputs inside dataset-specific directories in the repository working directory. These include:

- train/test/validation arrays;
- coalition matrices;
- coalition accuracy and F1 values;
- Shapley/Banzhaf/least-core/excess-norm allocations;
- feature-selection evaluation tables;
- execution-time summaries;
- plots and auxiliary CSV files.

These generated directories are ignored by Git. The `results/` directory is provided as a clean location for any consolidated tables or figures that you may choose to export for publication.
